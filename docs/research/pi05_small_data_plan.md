# π0.5 subtask 小数据适配：官方证据、FAST 对照与架构方案

日期：2026-10-20。性质：离线研究结论和待验证方案。
生产模型、训练默认配置、真机服务均未修改。

## 结论及其限度

当前证据支持：继续压低 FAST 训练 CE 不是可靠的模型选择策略；FAST
在当前小数据微调中未证明收益，补充对照出现轻微负作用迹象，但尚不能确认。
不应把“能记住 16 个样本”解释为架构正确，也不能把“过拟合”作为最终根因。

下一轮应优先比较：直接从已有 π0.5 动作权重保守适配，和现有的
“冻结 expert、全量更新主干的 Stage1，再联合训练”流程。
FAST 设置为可消融的辅助目标；是否保留由独立数据上的动作与任务指标决定。

## 官方事实

π0.5 原论文采用共享模型的高层/低层推理，包含广泛的数据混合和视觉增强；
附录的动作条件前缀为双向，FAST 为因果，expert 不读取 FAST。
论文也评估了不显式生成高层文本的 implicit HL。
[π0.5 原论文 IV、V-E、A-E](https://arxiv.org/html/2504.16054v1)。

后续 KI 研究把 FAST 作为表征监督，并阻断 flow 向主干的梯度；其结论来自
完整训练配方和任务实验，不能直接证明小数据适配时 FAST 必不可少。
[KI 论文](https://www.pi.website/download/pi05_KI.pdf)。

官方开源库明确说明：目前 π0.5 训练/推理仅支持 flow head。
这说明继续微调时不加 FAST 是合理对照，并不证明预训练阶段的 FAST 无用。
[官方 README](https://github.com/Physical-Intelligence/openpi#readme)。

FAST 使用 DCT、量化和 BPE 表示动作。由此推导，token CE 不等于连续控制误差，
尤其不能把不同动作序列中的 token 错误视为同样大小的物理偏差。
[FAST 论文](https://arxiv.org/html/2501.09747v1)。

## 已确认的本地实现与待验证机制

| 本地事实 | 机制假设 | 证据边界 |
|---|---|---|
| 93 个训练 episode；主干/视觉全参数更新；本训练入口无随机图像增强 | 记忆场景、遗忘已有表征 | 没有证明某一项独立导致失败 |
| Stage1 冻结已有 expert，主干 LR 1e-4；Stage2 恢复联合训练 | 主干变化后，已有 expert 接口失配 | 需要从相同初始 VLA 权重比较是否跳过该阶段 |
| FAST 读因果文本上下文，flow 读重建的双向文本上下文 | 辅助任务学到的表示与执行表示不完全一致 | 不能用推理时改 mask 的退化直接证明原训练目标有害 |
| flow 训练/验证给 GT subtask，运行时给生成 subtask | 高层错误传给动作分支 | 12 条样本替换条件后动作误差增加，尚非成功率证据 |
| subtask 边界截断动作、尾部补零，仅屏蔽 loss；attention 仍访问尾部 | 有效动作受无监督尾部影响 | 扰动实验证实耦合，但未证明现场抖动由此引起 |

修正前次讨论：

- 官方高层公式也以当前观察为条件；没有历史记忆不是已证实的复现错误。
- 高层生成 subtask 必须使用因果目标掩码，不能把整条含答案序列改成双向。
- flow 不读 FAST 是防止真实动作信息泄漏的正确设计。
- KI 仅阻断 flow 梯度，不会阻止 FAST 自身记忆训练数据。
- 不应直接比较论文与本库的 loss 系数；sum/mean、token 数和有效动作维数的
  归约不同，会改变梯度尺度。

## 补充：FAST × 梯度隔离的 2×2 对照

此前四组实验全部包含 FAST，无法判断 FAST 的边际作用。
本次新增两种零 FAST 权重配置，重跑四组匹配实验。

共同条件：step-750 起点、同一组训练 16 条/验证 16 条、seed 1702、
32 updates、effective batch 4、LR 2e-5、AdamW、BF16。
每个划分各 8 条短/完整 horizon；训练/验证 episode 不重叠。
初始模型与评估结果完全一致；每组 32 次更新均正常完成。

动作指标：GT subtask，固定每样本噪声，10 步去噪；按有效元素汇总的
归一化动作 MSE。与训练时的单步速度场 MSE 分开统计。

| 目标 | flow 梯度隔离 | 验证纯 FAST CE | 验证 flow MSE | 验证采样动作 MSE ↓ |
|---|---|---:|---:|---:|
| 共同初始值 | — | 4.0294 | 0.031769 | 0.066135 |
| subtask + FAST + flow | 否 | 4.3588 | 0.032186 | 0.063688 |
| subtask + flow | 否 | 4.0379 | 0.032645 | 0.061930 |
| subtask + FAST + flow | 是 | 4.3478 | 0.032121 | 0.064667 |
| subtask + flow | 是 | 4.0242 | 0.032148 | 0.061648 |

权重分别为 `0.15 / 0.15 / 1` 与 `0.15 / 0 / 1`。
关闭 FAST 后，两种梯度设置的采样动作 MSE 分别低 2.76% 和 4.67%。
这只是轻微负作用迹象，不构成统计显著结论：

- 只有 16 条验证样本、一个训练 seed、每样本一个去噪噪声。
- step-750 已经过 FAST 训练；这测的是继续训练时的边际作用，
  不是否定 FAST 的预训练价值，也不能排除此前 Stage1 已产生影响。
- 评估给定 GT subtask，没有覆盖完整生成链与闭环任务。
- 一条示范只是多种可能成功动作之一；动作 MSE 不是成功率。
- 关闭 FAST 的分支仍执行相同高层 forward，只把 action CE 权重置零，
  因而本实验不衡量删除分支后的训练加速。
- 本次重新运行的 BF16 数值与前一轮存在小幅差别，应使用本表内的匹配对照，
  最终比较需要多 seed 和按 episode 的不确定性统计。

复现：

```bash
python scripts/diagnostics/ablate_fast.py \
  --bundle "$BUNDLE" --subset "$SUBSET" \
  --arm subtask_flow --updates 32 --batch-size 4 --lr 2e-5 \
  --evaluate-actions --output artifacts/fast_off
```

2×2 arm 为 `hybrid`、`subtask_flow`、`hybrid_insulated`、
`subtask_flow_insulated`。数据格式见 [FAST 诊断报告](../fast_audit_20261020.md)。

## 建议架构：保守适配已有 VLA，分开评价规划与控制

以下是本项目建议，不是官方原样实现或已验证最优架构。

### A. 先建立无需 FAST 的小数据基线

从原 π0.5 base 或有可靠任务评估的无 subtask 权重启动，保留已有 action expert。
跳过长时间、全参数的 FAST-only 适配阶段。

限制视觉/语言底座的更新：优先试冻结视觉底座、VLM 上低秩 adapter，
保留 expert 的任务适配。adapter rank 8/16、较低学习率只是候选起点，
不能宣称可以保证泛化。若冻结视觉明显欠拟合，再单独比较视觉末层解冻，
不一开始同时改动全部参数。

先保留当前两次前向的组织方式，训练 `subtask CE + flow`。
如梯度诊断与实验确认规划/控制存在冲突，再比较独立的高层/动作 adapter：
共享冻结底座，语义 adapter 学高层，动作 adapter 与 expert 学控制，
通过可读 subtask 连接。这样缩小可变参数和相互干扰范围；仍需验证容量是否足够。

不要把“冻结通用 VLM 后随机训练 expert”与“保留已有 VLA 再做有限适配”混为一谈。

### B. 保留 FAST 时，让它监督真正用于执行的条件表征

高层任务单独生成 subtask：

```text
图像 + 状态 + 总任务 → 高层条件前缀 → 因果 subtask 目标
```

动作任务先构建唯一的双向条件前缀，供 FAST 与 flow 共用：

```text
图像 + 状态 + subtask → 双向动作条件前缀
                       ├─ FAST 自回归目标
                       └─ flow expert → 连续动作
```

FAST 与 flow 互相不可见；对照是否在 expert 读前缀时 stop-gradient。
推理使用预测的 subtask 重新构建动作前缀，遵守相同 token、mask、位置编号规则。
高层生成 KV 不直接替代这个双向动作前缀。
是否保留总任务作为动作条件，单独设置开关，不和其他改动混在一起评价。

这样统一的是动作表征学习与动作执行的条件，不是把高层目标改成双向。
若 FAST 关闭，是否阻断 flow 梯度应重新评估；不能机械套用 KI，
使所有动作相关的主干适配都失去学习信号。

### C. 以观察到的完成状态处理跳变

若连续评测确认阶段边界是主要错误来源，再增加阶段完成预测或短历史条件。
任务头可尝试结构化的“手臂/操作/对象/目标位置”，减少固定句式 token
对语义准确率的掩盖；保留文本能力作为辅助目标。

不能只用固定时间保持标签，也不能在所有相邻帧上强制同一标签。
边界监督必须与真实完成状态核对；历史输入同样要在训练与部署时提供。
训练后若预测错 subtask，应补充这些观察上的高层纠正标签；不要直接把错误
subtask 与原动作配对训练，避免教会控制器忽略语言。

### D. 整理动作目标与增强

优先核对阶段边界的动作定义。对照固定 horizon 与显式结束/有效长度建模；
不能用 GT 剩余长度作为部署不可得的输入，也不能仅在推理时加未知长度 mask。
“最后姿态保持”只有在任务语义与数据证据支持时才能作为尾部监督，
不能把所有截断尾部随意补成停止动作。

缓存保留确定性解码；随机增强在训练取样后执行。先使用轻度亮度、对比度、
裁剪等保持任务语义的增强；验证不增强。避免未经动作/标签同步变换的左右翻转，
或改变关键颜色语义的强增强。

## 能决定 FAST 去留的正式实验

1. 固定数据划分、初始化、动作目标、mask、优化器和采样顺序，比较 FAST
   权重 0、低权重、当前权重。分别报告同更新次数和同训练成本结果。
2. 先在同一 Stage2 起点测边际作用，再从相同原始 VLA 起点比较有/无
   FAST-only 适配阶段，避免把历史影响误认为当前 loss 的影响。
3. 梯度隔离、共享动作条件前缀、限制参数更新分别比较，不一次全部改动。
4. 至少 3 个训练 seed；按 episode 汇总误差和 bootstrap 区间，
   不能把同轨迹的相邻帧当成独立试验。
5. 评估 GT subtask 与生成 subtask 两种动作条件；记录句级/槽位准确率、
   阶段内跳变率、真实边界检测延迟，以及关节/夹爪误差和多噪声动作采样。
6. 加入图像/状态/文本干预与共享参数梯度夹角作为机制诊断；
   梯度冲突本身不是删除 FAST 的充分条件。
7. 现有验证集已用于决策，最终需保留未调参的独立测试轨迹；场景/物体/
   采集时间可分组时，额外做分组泛化测试。
8. 最终以任务完成、选对对象和动作稳定性决定是否部署；离线 MSE 只做筛选，
   真机验证另行执行，不在本次研究中自动启动。

FAST 的验收条件是：在这些对照下改善动作或任务泛化，同时没有不可接受的
语义退化。如果只是训练 CE 更低、验证动作无收益，应关闭或降低其权重，
而不是为贴近论文形式继续保留。
